## What this is
**pdl-bench**: a research benchmark for parallel & distributed CNN training, written from
scratch in C11 + MPI + OpenMP + CUDA, with Python tooling for experiments and analysis.
It reproduces and extends Hegde & Usmani, *Parallel and Distributed Deep Learning*
(https://hgpu.org/?p=16046, not stored in the repo) following the team's spec (`docs/reference/overview.md`;
decisions about it are in `docs/SPEC_REVIEW.md`).

* **Target machine**: Intel i5-12600K (6P + 4E cores, 16 threads), NVIDIA RTX 2060 6 GB
  (sm_75), Ubuntu or WSL2, OpenMPI. The code was written on a Mac without a GPU.
* The user explicitly does **not** want detailed unit tests. Correctness is covered by
  `pdl_check` + `ctest`. Don't add per-function unit-test suites.

## Commands
```bash
scripts/setup_ubuntu.sh                 # apt deps + .venv (Ubuntu/WSL2)
scripts/build.sh [--cuda on|off|auto]   # CMake Release → build/bin/
ctest --test-dir build --output-on-failure      # ~10 s CPU; -L quick skips MPI launches
build/bin/pdl_check --device both               # gradients, kernels CUDA vs CPU, determinism
mpirun -np 4 build/bin/pdl_check --tests allreduce,equivalence,sync
pdlbench data --dataset mnist cifar10           # → data/*.pdlds   (pip install -e . or PYTHONPATH=pytools)
pdlbench all configs/<exp>.yaml                 # run + aggregate + plot + perfmodel + report
scripts/run_all.sh [--cpu-only]                 # whole suite
```
Binaries: `pdl_train` (strategies), `pdl_bench_compute` (paper §3), `pdl_bench_comm`
(allreduce algorithms, ping-pong α/β), `pdl_check` (correctness). Every option: `docs/CLI.md`.

## Code map
* `include/pdl/*.h`: documented API contracts. Read the header before changing a module.
* `src/backend/`: `backend.c` dispatches on `ctx->device`; `cpu_kernels.c`
  (naive/blocked/omp); `cuda_kernels.cu` (naive/tiled/cublas + CNN kernels). Internal
  prototypes are generated by the `PDL_DECLARE_KERNELS` macro in `internal.h`.
* `src/nn/model.c`: spec parser (`conv:OC:K:S:P,relu,pool:K:S,fc:N`), presets, forward/backward.
* `src/data/dataset.c`: `.pdlds` format, lazy synthetic data keyed by (seed, index), partitions.
* `src/comm/comm.c`: allreduce `mpi|ring|rd|tree|naive|reduce_bcast`.
* `src/train/`: `config.c` (option table → parsing, `--help`, JSON config), `trainer.c`
  (shared runtime, results JSON), `strategy_*.c`.
* `apps/`: the four programs. `tests/CMakeLists.txt`: CTest registration.
* `pytools/pdlbench/`: `data`, `envinfo`, `config` (YAML schema), `runner`, `aggregate`,
  `plots`, `perfmodel`, `report`, `codemetrics`. `configs/*.yaml` is the experiment suite.

## Invariants (don't break)
1. **JSON schema is a contract** with the Python tooling (`docs/RESULTS_SCHEMA.md`). If you
   change keys, update both sides and the doc.
2. Config keys in results = CLI names with `-` → `_`. New `pdl_train` options go in the table in
   `src/train/config.c`, which records them automatically. Update `docs/CLI.md`.
3. All parameters/gradients live in one flat buffer, and layers store offsets only, never pointers.
4. Allreduce algorithms must give **bitwise-identical** results on all ranks (`--check-sync`
   and `pdl_check sync` rely on it).
5. Every collective (MPI call) must be reached by all ranks. Rank-0-only code must not call
   collectives (e.g. `pdl_env_write_json` is non-collective, so pass `hosts` computed collectively).
6. Kernels stay deterministic (no atomics in reductions that feed parameters).
7. Timed regions exclude evaluation. GPU phase timing syncs only when `ctx->timing_sync`.
8. Each strategy must produce exactly `epochs` records per rank (the result gather assumes it).

## Gotchas learned during development
* `mpiexec` reads stdin: in shell loops use `mpirun ... < /dev/null`.
* zsh does not word-split `$var`. Run multi-arg shell loops with `bash`.
* Finite differences cross ReLU/max-pool kinks. The gradcheck skips probes whose activation
  signature changes. Don't "fix" failures by raising the tolerance.
* Executables link with the C compiler (not nvcc) because MPI link flags break nvcc. pdl_core
  links `CUDA::cudart` + `stdc++`.
* OpenMPI needs `--oversubscribe` above physical cores and `--allow-run-as-root` as root.
  The Python runner handles both, and ctest adds `--oversubscribe` for OpenMPI.
* `paper` model at batch 256 needs ~3.5 GB GPU memory (im2col of conv2 dominates).
